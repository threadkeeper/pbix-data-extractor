> **TL;DR** — Open your `.pbix` in Power BI Desktop, run two scripts, get a full SQL database. That's it.

## 🗺️ What's in this repo

| File | Purpose |
|---|---|
| 🐍 `extract_schema.py` | Connects to the running Power BI Desktop SSAS model to read the full table/column schema and generates `create_tables.sql`. Falls back to parsing the `.pbix` layout if SSAS is unavailable. |
| ⚡ `extract_data.ps1` | Connects to the running Power BI Desktop SSAS model, reads every table's data, and generates `insert_data.sql` + pipe-delimited CSVs in `data/`. |
| 📋 `create_tables.sql` | Generated `CREATE TABLE` script (created by `extract_schema.py`). |
| 📦 `insert_data.sql` | Generated `INSERT` statements (created by `extract_data.ps1`). |
| 📂 `data/` | Pipe-delimited CSV exports of every table (created by `extract_data.ps1`). |

## ⚓ Prerequisites

- 🪟 **Windows** (Power BI Desktop is Windows-only)
- 📊 **Power BI Desktop** installed ([download](https://powerbi.microsoft.com/desktop/))
- 🔌 **ADOMD.NET** client library — installed automatically with Power BI Desktop or SSMS
- 🐍 **Python 3.6+** — required for `extract_schema.py`
- 🗄️ **SQL Server** (local or remote) to import the data into

## 🏴‍☠️ Step-by-step guide

### Step 1 — 📂 Open the `.pbix` file in Power BI Desktop

1. Copy your `.pbix` file into this folder (or note its path).
2. Double-click the `.pbix` file to open it in **Power BI Desktop**.
3. Wait for it to fully load (all visuals rendered, no loading spinners).

> Power BI Desktop starts a local Analysis Services (SSAS) engine in the background. Both scripts connect to it automatically.

### Step 2 — 🐍 Generate the table schema

Open a **PowerShell** terminal in this folder and run:

```powershell
python extract_schema.py
```

This connects to the live SSAS model, reads all tables and columns with their data types, and generates `create_tables.sql`.

If Power BI Desktop is not running, it falls back to parsing the `.pbix` layout file (requires extracting the `.pbix` first — see [Fallback mode](#fallback-schema-discovery-without-power-bi-desktop) below).

### Step 3 — ⚡ Generate the data

```powershell
.\extract_data.ps1
```

This connects to the same SSAS model and:
- Reads all rows from every table (batched in groups of 5,000)
- Generates `insert_data.sql` with INSERT statements
- Exports each table as a pipe-delimited CSV in the `data/` folder
- Shows progress every 1,000 rows for large tables

### Step 4 — 🗄️ Create the tables in SQL Server

Run `create_tables.sql` against your target database:

```powershell
sqlcmd -S localhost -d YourDatabase -i create_tables.sql
```

Or open it in **SSMS** / **Azure Data Studio** and execute.

### Step 5 — 💰 Load the data

Run the generated INSERT script:

```powershell
sqlcmd -S localhost -d YourDatabase -i insert_data.sql
```

**Alternative — bulk load from CSV (faster for large datasets):**

```sql
BULK INSERT [YourTable]
FROM 'C:\path\to\data\YourTable.csv'
WITH (
    FIELDTERMINATOR = '|',
    ROWTERMINATOR = '\n',
    FIRSTROW = 2,
    CODEPAGE = '65001'
);
```

### Step 6 — ✅ Verify

```sql
SELECT 'TableA' AS TableName, COUNT(*) AS Rows FROM [TableA]
UNION ALL
SELECT 'TableB', COUNT(*) FROM [TableB]
UNION ALL
SELECT 'TableC', COUNT(*) FROM [TableC];
```

## 🔮 Fallback: Schema discovery without Power BI Desktop

If Power BI Desktop is not running, `extract_schema.py` can still generate `create_tables.sql` by parsing the `.pbix` layout file. First extract the `.pbix` (it's a ZIP archive):

```powershell
Copy-Item "YourReport.pbix" "pbix_extracted.zip"
Expand-Archive "pbix_extracted.zip" -DestinationPath "pbix_extracted" -Force
Remove-Item "pbix_extracted.zip"

python extract_schema.py
```

> **Note:** This fallback only discovers columns referenced in report visuals, not the full model schema. Use the live SSAS connection for complete results.

## 📝 Notes

- 🏷️ Tables suffixed with `(2)` in Power BI are renamed without the suffix in SQL (e.g., `MyTable (2)` → `MyTable`).
- 🔒 The Power BI `Table` entity is renamed to `FactTable` to avoid the SQL reserved word.
- 🚫 Internal Power BI tables (`LocalDateTable_*`, `DateTableTemplate_*`) and `RowNumber` columns are automatically excluded.
- ⚠️ Some tables may be DAX calculated tables — if they don't map to source data, you can skip them.
